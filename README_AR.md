# تصحيحات واجهة SNNS.PRO (غير منشورة)

تم تعديل ملفين فقط بناء على النصوص المرفوعة، دون تعديل الخادم أو قواعد البيانات.

- توجيه الطلبات إلى `VITE_API_BASE_URL` مع قيمة افتراضية `https://api.snns.pro`.
- إرسال Firebase ID Token في جميع طلبات البريد (الوارد/المرسل/القراءة/الحذف/الإرسال)، وعدم تنفيذ طلب البريد دون جلسة.
- معالجة فشل HTTP في جلب البريد بدل اعتباره صندوقًا فارغًا.
- تصفير صلاحيات الإدارة عند فشل التحقق.

## شروط مهمة قبل الدمج
1. يجب أن يدعم خادم API المسارات المذكورة وأن يتحقق من Firebase ID Token ويشتق عنوان صندوق المستخدم من التوكن، لا من البريد المرسل في URL أو body.
2. لا يجوز اعتماد فلترة `recipient === email` وحدها كحماية.
3. ما زال adminService يستخدم passcode في localStorage: هذا خلل تصميمي قائم يتطلب تعديل عقد المصادقة في الخادم ليستخدم جلسة HttpOnly آمنة أو Firebase admin claims. لا تعتبر هذا الملف حلًا نهائيًا لمصادقة الإدارة.
4. يلزم إعداد CORS للسماح بـ `https://snns.pro` و Authorization وطرق PATCH/DELETE/POST/GET.
5. `realMailService` وserver.ts لم يرفعا ضمن الملفات الحالية؛ لا يمكن ضمان التوافق أو إثبات اختبارات التشغيل دون المشروع الكامل.
6. احفظ نسخ الملفات الأصلية واختبر tsc/build والتكامل في بيئة تجريبية. لا تنشر قبل التحقق.
